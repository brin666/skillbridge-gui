# 交接包与数据契约

状态：v1 产品语义契约。核心档案与交接包已实施，完整的目标管理仍分阶段推进。可调用字段与限制见[后端接口](backend-api.md)，其中的路由与响应为 GUI 对接依据。

## 1. 数据根目录

沿用用户级 ~/.skillbridge，已支持 SKILLBRIDGE_HOME 和 CLI --data-dir（优先级更高），所有入口共用解析规则。结构化档案保存在 profile.sqlite3。

所有入口使用相同解析规则。显式设置无效时报告错误，不静默切换到其他目录。现有 cache、library、history 数据保持原位；结构升级要备份、识别版本并可恢复。

| 数据 | 作用 |
|---|---|
| 结构化档案 | 资产身份、位置、修订、常用确认、推荐和使用证据 |
| 中央库 | 用户选择保存的完整资料副本 |
| 购物车草稿 | 本次选择、任务、项目、可选目标和草稿版本 |
| COMMON_SKILLS.md | 从档案生成的可读视图，注明生成时间；不是另一个独立可写事实源 |
| handoffs/<package-id>/ | 固定的交接资料快照 |
| 接收报告与任务账本 | 按包和环境关联的动作、反馈及证据 |
| 受管写入快照 | 目标配置修改前的内容和修改范围 |

profile.sqlite3、COMMON_SKILLS.md 和 handoffs 已实施；中央库沿用旧能力，受管写入快照尚未实施。存储实现见[架构](architecture.md)。这些数据不写入项目源码目录。

## 2. 关键对象

| 对象 | 必须表达的信息 |
|---|---|
| Environment | 实例 ID、Harness 类型、已知版本、配置根目录、可选 Agent／模型信息、项目范围 |
| Asset | 稳定 ID、类型、标题、来源、所属范围、系统／用户／未知归属 |
| AssetRevision | 修订 ID、内容指纹、文件清单、获取时间、来源版本（可未知） |
| Location | 对应资产修订、环境、实际路径、可读状态、启用状态、最后核查时间 |
| Observation | 报告 ID、来源环境、资产、观察时间、证据类型、可用的计数或用户偏好 |
| Preference | 已确认常用／取消常用、适用范围、确认来源与时间；与观察记录分开 |
| Cart | 草稿 ID 与版本、选择项、项目、任务说明、可选目标 |
| HandoffPackage | 固定包 ID、清单版本、选定修订、内容快照、包含／排除范围、待处理项 |
| Receipt | 包 ID、目标环境、报告来源、逐项动作与状态、时间和证据 |
| TaskRecord | 任务类型、环境／模型配置、用户评价、验证结果、返工、耗时、费用及来源 |

语义版本缺失时用内部修订区分，不伪造版本号。只凭同名、相同文件夹名或修改时间不能合并资产。

来源相同且内容相同的副本可以关联多个位置；来源无法确定时保留独立候选或交由用户关联。路径指向同一文件时避免重复计数，同时保留被哪些环境引用的关系。

## 3. Agent 提交资料

Agent 通过明确调用提交结构化报告。最低字段为报告 ID、报告来源、时间、资产引用、报告类型和内容。

报告类型包括常用推荐、使用观察、记忆草稿、规则转换建议和接收结果。相同报告 ID 重复提交不能累计使用次数。部分报告无法解析时保留明确的失败项，不丢弃已有效接收的数据。

无证据的次数与时间为空。Agent 推荐或转换稿默认待确认，不自动改变用户确认过的规则、记忆或常用范围。

结构化文档的更新由统一程序完成，支持并发写入与草稿版本检查，避免两个 Agent 直接互相覆盖 Markdown。

## 4. 购物车选择快照

选择项至少包含 assetId、revisionId、类型、加入时间、选取范围和用途。Skill 默认选择完整文件夹；记忆选具体摘要；规则选具体文档或明确片段；MCP 选明确服务配置；账本选明确记录或摘要。

生成前以草稿版本核对选中修订。来源变化时返回可展示的差异；用户选用新修订或已保存旧副本后再生成。

已生成包不可原地更新。修改草稿再次生成产生新包。长期常用状态和本次选择独立。

## 5. 交接包目录建议

```text
<package-id>/
  manifest.json
  README.md
  HANDOFF.md
  payload/
    skills/<asset-id>/...
    rules/<asset-id>/...
    memories/<asset-id>/content.md
    mcp/<asset-id>/config.json
    ledger/<asset-id>/content.json
```

- manifest.json 供程序读取。
- README.md 是接收方阅读入口，解释任务、项目、选定资料和待处理项。
- HANDOFF.md 是按[提示词模板](templates/handoff-prompt.md)生成的用户可复制文本。
- payload 保存实际副本，不以源机器路径替代内容。原始绝对路径仅作为来源线索和项目位置说明。
- 包内文件使用相对路径，文件来源保留原文件名，内联来源使用上面的 content 名称。接收方以包实际位置定位文件；首版提示词指向同机导出位置，移动包后的入口重定位尚未实现。
- 项目路径默认是工作位置，不代表打包整个项目代码；如需附带项目文件，应让用户明确选择。

## 6. manifest v1 必备字段

| 字段 | 类型 | 含义 |
|---|---|---|
| schemaVersion | integer | 清单结构版本，首版拟为 1 |
| packageId | string | 唯一包 ID |
| createdAt | string | 带时区的 ISO 8601 时间 |
| generator | object | 生成器名称与版本 |
| task | object | 用户提供的任务说明；可为空说明，不能由程序虚构任务 |
| project | object 或 null | 项目 ID（若已知）、标签和源路径 |
| targetHint | object 或 null | 用户提供的目标提示，不是兼容性结论 |
| items | array | 所选资产、来源、修订、范围、用途和包内入口 |
| files | array | 每个 payload 文件的相对路径、字节数和 SHA-256 |
| omissions | array | 未包含的内容、原因，以及用户已审阅的处理方式 |
| followUps | array | 待补依赖、凭据、路径或人工决定；不推测所有目标兼容性 |

items 中的包内入口必须能在 files 中找到，或明确为指向已列文件的目录。路径不能逃出包根目录。哈希用于发现损坏，不证明来源可信，也不构成写入授权。

## 7. 文件处理与完整性

1. 在新临时目录准备导出，不覆盖同 ID 的已有完整包。
2. Skill 包含所选目录中的文档、脚本、资源与配置模板，不静默遗漏为其服务的文件。
3. 不把 Git 历史、缓存、安装依赖目录或凭据自动装入普通包；排除项和受影响的重建要求可查看。
4. 对符号链接、目录联接或外部引用，明确记录实际关系。不能沿链接无限扩展扫描；需要的外部内容由用户补选后以普通文件副本纳入，或列为待补事项。
5. MCP 中的凭据值和访问令牌不进入普通包；保留变量名或占位说明。无法可靠分离敏感字段时提示用户审阅该配置条目。
6. 逐文件复制与核对。已选内容读取失败、源在复制过程中改变或输出损坏，不能发布一个显示“完整”的包。
7. 未能交付的已选内容由用户决定移除、替换或补齐；未选择的外部依赖可以保留为 followUps，不扩大兼容性检查。
8. 完成清单、资料和提示词后再发布完整包；失败保留购物车和错误信息，临时产物不冒充可交接结果。

删除临时产物只能针对本次明确创建、位于管理目录内的路径。普通导出不修改来源。

## 8. 提示词生成

提示词必须包含用户意图、项目位置、包入口、所选资料摘要、待处理项和操作范围。大量原始内容留在包中，不默认拼接完整会话到一条提示词。

默认提供“读取并提出处理方案”的表述。用户在预览中明确选择具体写入意图时，可生成携带该意图的指令；包内文档或清单自身不能授予额外操作权限。

接收方根据实际用户请求继续已授权工作，仅对新目标、冲突或扩大范围的动作询问。提示词不要求绕过目标环境的规则，不承诺获得应用内置工具或账号权限。

## 9. 状态契约

状态按对象保存，不能只用一个“成功”覆盖全过程。

| 对象 | 状态建议 |
|---|---|
| 购物车草稿 | draft、checking、needs_attention、ready、exporting |
| 导出任务 | running、complete、failed、cancelled |
| 包 | ready 或 ready_with_followups；完整性验证失败时不得进入可交付状态 |
| 接收动作 | read、written、recognized、verified、needs_action、failed、unknown |

written、recognized、verified 是不同证据，不是强制依次增加的百分比。例如已有安装可能直接被识别，单纯阅读记忆也不需要写入文件。

导出失败可重试；重复点击同一生成请求应返回同一任务，不能产生重复包。取消会停止后续工作，不宣称已回滚目标，因为普通导出没有写目标。

## 10. 接收回执与恢复边界

回执至少包含 packageId、报告 ID、目标环境、时间，以及每项资产的动作、状态、说明和证据来源。重复回执去重。未知或来自旧版本的状态按未知保留，不自动当作成功。

经 SkillBridge 受管执行器写入的目标文件，记录修改前快照、实际路径和结果。恢复前比较当前文件，保留备份后发生的用户修改。

接收 Agent 自行执行、或用户手动复制的动作，只能记录其报告；没有快照与动作证据时不能承诺自动恢复。
