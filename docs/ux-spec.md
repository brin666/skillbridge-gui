# GUI 与交互规格

状态：功能与交互要求，尚无新版视觉批准稿。本文件不授权直接改写正式界面。

## 1. 设计依据

- 用户指定的核心参考是购物车交互：浏览分类、选中条目、加入时产生落入购物车的反馈、统一预览并生成提示词。
- 现有界面、[DESIGN.md](../DESIGN.md) 和 ui/src 中的组件是复用起点。保留合适的中英文、状态反馈和无障碍能力。
- 新版颜色、字体、布局、卡片形态和动效节奏尚待预览确认。不要把旧界面记录当作用户已经批准的新设计。

## 2. 信息组织

默认进入 Skills。主要内容分类为 Skills、规则、记忆、MCP、账本。原对话中的“GE”名称未明确，文档采用“记忆”这一功能名，具体导航文案在预览时确认。

环境／项目上下文在各分类间保持一致。总览和待处理事项、历史、设置作为辅助入口；不要求每种状态单独建一个页面。

建议桌面内容区旁保持可见的购物车摘要；窄屏使用可直接打开的摘要和抽屉。位置与布局以预览为准。

## 3. 列表和详情

| 分类 | 列表重点 | 详情重点 |
|---|---|---|
| Skills | 名称、用途、来源、常用标记、已加入状态 | 文件位置、修订、配套文件、安装环境、使用记录来源 |
| 规则 | 标题、个人／项目范围、来源应用 | 原文、可选转换稿、差异、冲突、应用专属部分 |
| 记忆 | 摘要主题、项目、确认／过期状态 | 摘要、出处、更新时间、纠正与删除、替代关系 |
| MCP | 服务名称、用途、配置来源 | 配置预览、依赖、凭据引用、连接检查结果及时间 |
| 账本 | 任务类型、应用／模型、结果 | 用户反馈、返工、耗时、费用来源、证据覆盖范围 |

查看详情与加入购物车是可区分的动作，避免用户为阅读而误加入。具体按钮位置在预览中展示。

系统内置技能不出现在默认可交接清单；来源未知时标明未知，不因名字像官方技能就自动排除。已确认常用优先展示，所有可管理用户资产仍可查找。

## 4. 购物车行为

- 加入立即生效，状态更新不等待动画完成。
- 同一条目重复点击不累计数量；可撤回加入。不同版本需要显示版本或来源以免误认。
- 切换分类、查看详情和返回时保留已选项目。
- 移除、清空、修改任务说明和恢复草稿有明确反馈；不触碰源文件。
- 摘要显示按类型计数、待处理条目和进入预览入口。
- 单个条目检查失败不清空其他选择。用户可补充、替换或主动移除后继续。
- 空购物车提供浏览入口，不能生成暗含全部资料的提示词。

## 5. 加入动效

用户希望条目“掉落”到购物车。预览需展示触发位置、结束位置、节奏，以及连续加入和反向移除时的效果。

只移动一个视觉副本或轻量标记，原条目的可操作位置保持稳定。快速连续操作、切换分类或关闭面板不会导致重复选中或卡住。

启用系统“减少动态效果”时，使用选中状态、数量变化和简短提示替代位移。键盘、触屏和无动画模式均可完成完整流程。

## 6. 交接预览

预览集中显示：任务说明、项目位置、可选目标、已选条目、实际包含内容、排除项、待补充事项、导出位置、生成的提示词。

默认不展示兼容评分或未经验证的“全部可用”。输出提示区使用可核实的状态：资料齐全、缺少文件、来源待确认、等待补充配置。

用户能区分“生成交接包”“复制提示词”和“安装到目标”。本轮核心按钮为前两项，不能复用旧“一键同步全部”的行为。

提示词生成后可阅读和复制。若支持编辑，编辑稿与基于清单自动生成的原稿区分保存；编辑文本不自动改变已导出的包。

## 7. 状态与结果

| 状态 | 必须呈现的信息 |
|---|---|
| 整理中 | 已得到的分类和正在处理的范围 |
| 部分结果 | 可用条目、失败来源、继续使用与重试入口 |
| 没有档案 | 建立档案、扫描或指定位置 |
| 没有常用记录 | 待确认推荐和手动选择，不能伪造排行 |
| 导出中 | 正在保存的内容、明确的进行状态；可以停止后续工作 |
| 导出失败 | 失败条目、原因、保留的购物车及重试方式 |
| 包已生成 | 包位置、提示词、包含范围与待处理事项 |
| 已复制 | 仅表示剪贴板完成，不显示目标已安装 |
| 无接收结果 | 未收到报告，允许导入报告或记录用户反馈 |

## 8. 待处理事项

总览集中显示待确认推荐、外部文件变化、记忆冲突、缺失资料和未完成交接。每一项能进入来源详情，不使用缺少依据的健康总分。
