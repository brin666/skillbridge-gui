# 开发计划

状态：M2 后端基础已实施；用户将 GUI 放在另一会话开发。本会话不修改 ui/。M3 联调与 M4 真实接收尚未完成，阶段编号保留原规划顺序。

## 1. 当前交付

本轮在已有规格上交付 backend/workspace：SQLite 档案、资产修订、Agent 报告、分范围常用确认、购物车、固定包与提示词、回执、CLI 和 /api/v1。接口与联调步骤见[后端契约](backend-api.md)。旧同步入口保留，新入口不依赖旧兼容检查。

## 2. 建议阶段

| 阶段 | 对应需求 | 交付 | 完成条件 |
|---|---|---|---|
| M0 开发准备 | 全部 | 确认文档理解、记录代码基线、选择首批验证环境、准备代表性样本 | 范围无矛盾；不把未知平台支持写成已完成 |
| M1 体验预览 | F03、F04 | 内容分类、购物车、包预览、加入动效和窄屏预览 | 用户确认参考与预览；保留修订记录 |
| M2 数据与导出基础 | F01、F02、F04 | 档案入口、资产修订、报告、常用偏好、购物车、固定包与提示词 | 用临时样本完成可读且完整的导出；不调用全 Harness 兼容检查 |
| M3 GUI 接入 | F03、F04 | 将 M1 确认的界面连接真实数据、预览、复制和错误状态 | GUI 与 CLI 对同一草稿得到一致选择和结果 |

M2 已用临时目录中的合成资料完成数据与导出验证；正式网页及动效仍按 M1 预览流程推进。GUI 会话可直接使用 /api/v1 接入。

## 3. 首个闭环的内容

首个可交付闭环必须覆盖：获取资料 → GUI 明确选择 → 生成实际包 → 复制提示词 → 目标 Agent 阅读 → 展示有依据的结果。

Skills 要覆盖带脚本和素材的文件夹。规则、记忆和 MCP 可先通过明确的资料文件或 Agent 报告进入，暂不要求自动读取每家应用的全部格式。首个闭环保留原文和人工审阅，不承诺自动语义转换或 MCP 自动安装。

账本先保留有数据来源的设计和接口边界，未实现时不展示假榜单。完整的 F08 随 M6 交付，不能从产品清单中遗失。

## 4. 实施注意事项

- 不立即删除旧同步引擎。先让新导出器独立工作，明确旧界面的保留／退役方案后再调整。
- 现有 SkillBridge Skill 的说明随真实命令实现同步更新，避免文档先要求调用不存在的接口。
- 真实样本必须来自用户授权范围或专门测试目录。测试包不要混入个人档案、凭据或整个项目。
- 对接新 Harness 只核实当前需要的位置、格式与实际接收行为，不展开通用互通研究。
- 不新增云服务、账号系统、独立模型付费接入或多 Agent 自动调度作为前置条件。
- 本工作区中无关的 astryx 文件保持原样，不能加入本项目提交。

## 5. 验证分工

| 验证方式 | 覆盖内容 |
|---|---|
| 单元／契约测试 | 资产身份、报告去重、草稿修订、文件范围、清单与提示词对应 |
| 临时目录集成测试 | 多文件 Skill 导出、失败清理、部分问题说明、并发和旧档案兼容 |
| 浏览器验证 | 分类切换、购物车、连续加入、复制、错误状态、键盘与减少动态效果 |
| 真实 Harness 验证 | 提示词能否被使用、文件能否读取、明确目标是否识别选中内容 |
| 受管写入验证 | 快照、冲突处理、重复执行、恢复后续用户修改的保护 |

已有 199 项测试记录只是旧能力基线。新能力要建立有意义的验证，不以大量镜像实现的测试替代实际交接。
