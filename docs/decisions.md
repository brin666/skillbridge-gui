## 已确认的方向

| 编号 | 决定 | 实施影响 |
|---|---|---|
| D01 | 在 D:\skillbridge 改造，原项目保留 | 不改原始开发和发布目录 |
| D02 | GUI 为主要管理工作台，保留 Skill 与 CLI | 共用数据与业务逻辑，不做互不相通的三套工具 |
| D03 | 用户数据默认存用户自己的电脑 | 没有开发者服务器托管或账号系统的默认前提 |
| D04 | Agent 推荐常用 Skill，用户确认 | 推荐与已确认偏好分开保存 |
| D05 | 用户像购物车一样选择内容 | Skills 默认入口，分类切换保留选择，加入有可见反馈 |
| D06 | 常用仅为默认候选，本次选择决定范围 | 可以临时加入非“常用”内容，移除不改变长期偏好 |
| D07 | 内置系统技能默认不交接 | 主要管理用户资产，归属依据不能仅靠名称猜测 |
| D08 | 生成交接包及可复制提示词 | 包含项目位置、所选记忆／技能等，源端普通导出不直接安装目标 |
| D09 | Skill 带上配套文件 | 不沿用仅复制 SKILL.md 的同步路径作为导出器 |
| D10 | 缩减通用兼容性检查 | 不做全 Harness 矩阵，不用未知兼容性阻断资料导出 |
| D11 | 保留基本完整性与实际冲突检查 | 不能把漏拷、不可读或写入冲突当作成功 |
| D12 | 规则、记忆、MCP 和任务表现纳入产品 | 见 PRODUCT.md 的 F05—F09；不等同于自动调度多个 Agent |
| D13 | 先创建基础文档，然后准备开发 | 文档阶段已完成，后续开发授权见 D15 |
| D14 | 视觉与动效先预览后实施 | 购物车结构和加入动效需要直观预览确认 |
| D15 | 2026-11-11 开始 MVP 开发，GUI 在另一会话开发 | 本会话负责档案、CLI、API、购物车导出与接口文档，不改 ui/；不包含部署或推送 |

## 已被替代的早期方向

| 早期讨论 | 当前规则 |
|---|---|
| 只允许已确认常用 Skill 进入同步 | 常用提供默认候选，用户本次可主动选择其他资料 |
| 启动时全面检查跨 Harness 兼容性 | 导出做轻量完整性检查，实际接收问题由目标环境处理 |
| CLI 为主要产品入口 | GUI 为主要工作台，CLI 作为可独立调用的执行入口 |
| 选定全部 Harness 后互相补齐 | 按明确购物车选择生成交接资料，不自动全量补齐 |

保留历史记录用于解释变更，不能依据旧草稿恢复已放弃的产品门槛。

## 工程与交互建议（尚待验证）

| 编号 | 建议默认值 | 需要验证的内容 |

## 开发准备中需要进一步确定

| 问题 | 当前处理方式 | 最迟确定阶段 |
|---|---|---|
| 新界面参考、布局、字体和动效 | 依据现有界面与购物车意图做预览，不先写正式页面 | GUI 实施之前 |
| 首批真实验证的 Harness 与版本 | 代码有适配器不等于已验证；选能实际测试的环境，通用包不绑定名单 | 首次接收验证之前 |
| 系统内置资产的识别证据 | 优先使用明确的受管根目录和来源元数据；未知保持可见标签 | 资产分类实现时 |
| Agent 如何提交记录与 GUI 如何展示回流 | 初期显式调用，不承诺后台监控 | 报告入口实现时 |
| 规则转换由确定映射还是 Agent 建议完成 | 保留原文和差异，不保证任意格式无损互转 | 转换功能实现前 |
| MCP 首批读取／写入格式、连接测试方式 | 按目标逐个验证，凭据分开 | MCP 适配实现前 |
| 打包排除规则与外部引用策略 | 交接契约给出边界，具体默认清单需要实例验证 | 导出器实现时 |
| 如何给普通用户安装运行环境 | 需要完整可运行包和预构建 GUI，运行时打包方式未定 | 对外发布前 |
| 档案和快照保留期限 | 用户可见、可配置；不直接沿用外部草稿的“最近 10 次” | 自动清理功能前 |
| GUI 直接接模型、多设备和付费 | 不纳入当前核心承诺 | 后续产品决定 |

## 变更规则

新增范围或改变数据含义时先更新本文件及 PRODUCT.md，再更新相关流程、契约与验收。技术细节可以在已授权范围内落实，但不得用工程选择重新引入全量同步或兼容性评分。
