# 常用 Skill 识别与跨 Harness 迁移

> 历史讨论稿，已由后续购物车方案替代。下文保留当时讨论，不作为当前实施要求。当前规格见 [PRODUCT.md](../PRODUCT.md) 和 [决策记录](decisions.md)。特别注意：常用清单现为默认候选，手动选择决定本次范围；导出不再以通用兼容性预检为门槛。

日期：2026-11-11
状态：需求讨论稿；未实施功能或修改现有界面。

## 已确认的需求

- SkillBridge 作为 Skill 安装到不同 Harness 中，接收所在 Agent 提供的技能使用信息。
- 记录用户在各个 Agent、各个 Harness 中常用的 Skill，以及这些 Skill 的本地位置。
- 常用候选由 Agent 推荐，用户确认后才进入常用清单。
- 同步范围限定为用户确认的常用 Skill，不再默认同步所有已安装 Skill。
- 在同一台电脑、同一系统用户下，新 Harness 中的 SkillBridge 能读取共享档案，查找技能并判断迁移条件。
- 本次开发目录为 `D:\skillbridge`；原始项目目录保持不动。

## 建议的使用流程

1. 用户在已有 Harness 中调用 SkillBridge，例如“整理我常用的技能”。
2. Agent 根据实际可访问的使用证据提交候选、来源环境、技能位置和推荐理由。无法取得使用记录时明确说明，不从安装数量或文件修改时间推断使用频率。
3. SkillBridge 核查本地位置，区分技能身份、版本和副本，再呈现候选列表。
4. 用户选择需要保留的常用 Skill。Agent 推荐状态与用户确认状态分开保存。
5. SkillBridge 更新共享档案，生成可供人和 Agent 阅读的 Markdown 文档。
6. 用户在新 Harness 安装完整的 SkillBridge 包后，询问“哪些常用技能可以迁移过来”。
7. 新实例读取共享档案，重新检查源文件、目标能力和依赖，给出迁移计划。
8. 用户确认具体计划后执行迁移。确认“常用”不等于批准所有未来迁移。

## 共享档案

建议沿用项目现有的用户级 `~/.skillbridge` 数据根目录，不把个人档案存入某一份 SkillBridge 安装包或源码仓库。当前 Windows 用户的默认位置对应 `C:\Users\BL\.skillbridge`。允许统一配置数据根目录，以支持应用使用不同 HOME 或受限文件访问的情况。

建议使用结构化存储作为唯一数据源，再生成 `COMMON_SKILLS.md`。文档是供阅读的快照；推荐、确认和删除通过统一命令更新，避免多个 Agent 分别修改 Markdown 而互相覆盖。存储实现尚未确定，需要支持多进程并发、事务写入、结构版本和重复上报去重。

应记录：

| 信息 | 用途 |
|---|---|
| Harness 类型、实例及可识别的 Agent／配置标识 | 区分不同软件和同一软件的不同环境；无法识别的字段标为未知 |
| Skill 稳定身份、来源与版本指纹 | 区分同名不同源、同一技能的不同版本及多个副本 |
| 各环境的安装路径、启用状态和最后核查时间 | 帮助定位；迁移前仍需重新验证 |
| 观察到的使用事件或明确偏好、证据来源与覆盖范围 | 支持推荐，不把局部记录宣称为完整使用历史 |
| 最近使用时间和可验证的使用次数 | 无可靠记录时留空，不猜测次数 |
| 推荐理由、用户确认状态及确认范围 | 分开管理某个 Harness 常用与跨应用常用；跨应用范围由用户确认 |
| 迁移检查结果、目标版本与检查时间 | 保存有条件的检查结论，不宣称永久兼容 |

档案只需保存技能相关元数据和简短证据引用，无需收集完整对话或密钥。文件内的技能说明按数据处理，不能自行变成迁移执行指令。

## Agent 上报入口

建议先提供可独立运行的本地命令，接收结构化输入并输出 JSON，让安装在不同 Harness 下的 SkillBridge 共用同一套读写逻辑。无需先打开网页或维持后台 HTTP 服务。

- 上报观察记录／提交推荐：只形成候选，不自动成为已确认常用。
- 查询常用清单：按 Harness、Agent、跨应用范围查询，并可输出 Markdown。
- 保存用户确认：记录选择、来源和确认时间；新的推荐不能覆盖用户已有选择。
- 生成迁移计划：只针对确认范围检查目标；常用清单为空时提示整理，不能回退为全量同步。

上报时机尚待讨论：第一版建议在用户调用 SkillBridge 时整理并上报。若要求每次实际使用 Skill 都自动记录，需要逐个 Harness 核实和适配事件接口或可读日志。安装 Skill 文件本身不等于已建立持续使用统计。新 Harness 必须能访问共享档案和源文件；沙箱、不同系统用户或 WSL 需要显式的路径配置。

## 迁移检查与执行范围

- 对常用清单筛选之后再生成迁移计划，单目标、批量、中央库部署和互相同步入口使用一致的范围规则。
- 扫描仍可展示所有已安装 Skill；未被列为常用不代表卸载或删除。
- 在目标已安装相同版本、存在不同版本、源路径失效、资源缺失、能力不明等情况分别给出结果。
- 检查 `scripts/`、`references/`、`assets/` 等所需资源，以及运行时、外部工具、插件、MCP、账号或环境配置要求；缺失能力明确列出，不能仅因文件复制成功就认定迁移成功。
- 对需要附件的 Skill 制定完整包迁移策略，并展示文件清单。机器相关绝对路径和外部依赖需要人工处理或明确适配。
- SkillBridge 自身包含 Python 后端等文件，其安装与迁移不能只复制 `SKILL.md`。
- 计划绑定确认清单版本、源内容及目标状态；执行前复核变化，保留现有的冲突检测、临时校验和失败回滚。
- 静态检查通过、文件安装成功和实际任务验证通过分别记录。

## 验收场景

1. Agent 推荐 10 个 Skill，用户确认其中 3 个；同步计划只处理这 3 个。
2. 在第二个 Harness 安装 SkillBridge 后，可以读取第一处已确认的档案，并保留“在哪个环境常用”的来源。
3. 两个实例同时上报、或同一报告重复提交，不丢失记录、不重复计算、不自动改变用户确认。
4. 同名不同源及不同版本不会因名称相同而错误合并或覆盖。
5. 原路径失效、资源文件缺失或目标能力未知时，计划列明问题，不显示为可直接迁移。
6. 携带脚本的技能可以核查所需文件；安装完成与实际运行验证的状态分开呈现。
7. 空常用清单、不完整使用历史和无法访问共享档案都有明确结果，不回退为全量同步或虚构使用次数。

## 建议实施顺序

1. 先完成共享档案、Agent 命令和“推荐 → 用户确认 → 生成文档 → 新 Harness 查询”的最小流程。
2. 将确认清单接入全部同步入口，补齐依赖与完整包迁移策略。
3. 展示界面预览，确认后实现网页交互。
4. 如需要持续自动记录，再逐个接入有实际依据的 Harness 使用事件或日志适配器。
